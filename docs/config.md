# Routing systemd units through heimdall

How to make a systemd unit (or `heimdall run`-wrapped process) send
its egress through a specific heimdall connection — corporate VPN,
public internet, eBPF bypass, etc. **This file is the admin-side
overview.** For the full schema and validation rules see
`/etc/heimdall/README.md` on the host (auto-generated by `heimdall
init`).

## What heimdall gives a unit

Per-cgroup choice of:

1. **Which upstream egresses your traffic** — selected by a
   *connection name* (string, e.g. `default`, `corp`, `system`).
2. **Whether plaintext is captured** — observability flag.

Both are decided independently by the daemon on the host. Identity
comes from the cgroup path: heimdall parses the leaf unit
(`*.service` / `*.scope`) and its enclosing slice (`*.slice`)
straight off `/sys/fs/cgroup/<...>/cgroup.procs`.

## Connection names

Stable contract owned by the host admin (see
`/etc/heimdall/heimdall.ncl`). Names below are conventions used in
the project's defaults; your admin can add others.

| Name | Egresses to | When to use |
|---|---|---|
| `default` | Public internet via local SOCKS5 | github.com, npm, pypi, docker hub, public cloud APIs — anything that doesn't need a corporate VPN. **This is typically the host-wide default**; you only need to set it explicitly for clarity. |
| `corp` | A SOCKS5 endpoint behind a corporate VPN | Internal hostnames (e.g. `*.corp.example.com`), private git/registries, internal APIs, IP literals inside corporate VPN address spaces. |
| `direct` | Direct connect, no upstream proxy | Rarely needed. Useful if a unit needs the relay's logging but not the SOCKS5 layer. |
| `system` | **Skip heimdall entirely** (no eBPF redirect) | Host-bound infra (e.g. `containerd.service`, the local resolver) that must not pass through any user-space proxy. Reserved value — don't apply to application units. |

## How to route a unit

Two mechanisms.

### 1. `routing.rules` in `heimdall.ncl` (declarative, persistent)

Append a rule that matches the unit by its systemd identity. First
match wins (top-down):

```nickel
routing.rules = [
  { name = "vault-corp",
    match = {
      slices = [ "app.slice" ],
      units  = [ "prefix:vault-" ],
    },
    use     = "corp",
    observe = true,
  },
  { name = "noisy-infra",
    match = { units = [ "containerd.service", "node-exporter.service" ] },
    use     = "system",
    observe = false,
  },
]
```

`units` and `slices` are lists of `MatchValue`. A bare string is an
exact match; prefix-tagged strings give other strategies:

| Prefix | Semantics |
|---|---|
| (none) | exact match |
| `regexp:` | full-string regex |
| `prefix:` | starts-with |
| `suffix:` | ends-with |
| `keyword:` | substring (anywhere) |

Boolean composition (`all` / `any` / `not`) is available inside a
`match` block — see `/etc/heimdall/README.md`.

### 2. `heimdall run` (ad-hoc, per-invocation)

For one-shot CLI work, skip the config edit and wrap the command:

```bash
heimdall run --connection corp -- curl https://vault.prod.internal/
heimdall run --profile corp     -- git fetch origin
```

`heimdall run` creates a transient `heimdall-cli-*.scope` cgroup,
registers it via `POST /api/cli/register`, and tears it down on
exit. See [`skills/heimdall/references/run.md`](../skills/heimdall/references/run.md).

### Resolution order

```
heimdall run registration (per-cgroup_id override)
  > routing.rules[*]              (first match wins)
  > routing.default               (final fallback; default.use = "default")
```

## Suppress observability for a sensitive unit

Same rule shape, just flip `observe`:

```nickel
{ name = "regulated",
  match = { units = [ "payments-gateway.service" ] },
  use     = "corp",
  observe = false,    # tap events never fire for this cgroup
}
```

## Verifying it worked

Generate egress traffic from the unit and inspect the flow record:

```bash
systemctl restart my-app.service        # if you just changed config
sudo journalctl -u my-app.service -f &

# Hit the heimdall flow store from the host
curl -sS "http://127.0.0.1:9999/api/flows?limit=20" | jq -r '
  .[] | select(.connection_name != "bypass")
      | "\(.slice // "?"  )/\(.unit // "?"  )  →  \(.connection_name)  \(.dst_host // .dst_ip)"
'
```

| Result | Meaning |
|---|---|
| `connection_name = "corp"` | Rule matched. |
| `connection_name = "default"` | Rule didn't match — re-check the `units` / `slices` `MatchValue`. |
| No row | Either the unit made no egress yet, **or** routing resolved to `system` (eBPF skipped the relay), **or** the destination is in the bypass list (loopback / LAN / fake-IP pool). |

For deeper inspection (per-cgroup_id state, fake-IP mapping, captured
plaintext) point a browser at the heimdall UI:
`http://<host>:9999/`.

## Pitfalls

- **Don't set `use: system` on application units.** That bypasses
  the relay entirely — the unit gets *no* heimdall features (no
  SOCKS5 routing, no observability, no fake-IP DNS). Reserved for
  host infra.
- **Don't expect the unit's hostname to resolve via the upstream
  resolver by default.** If `dns: fake` isn't in effect for the
  cgroup, the unit's libc resolver hits the host resolver normally;
  fake-IP DNS only kicks in for `heimdall run` invocations with
  `--dns fake` (or units that opt in via config).
- **Loopback / LAN / link-local traffic doesn't go through
  heimdall.** Anything in the kernel-bypass CIDR set (loopback,
  RFC1918, link-local) is forwarded direct by eBPF and you don't
  need to do anything for it.
- **Don't add a new upstream from a rule.** New connection
  registrations are admin-only — they require credentials on the
  host. Edit `connections` in `heimdall.ncl`.
