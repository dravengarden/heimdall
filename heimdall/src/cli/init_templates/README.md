# /etc/heimdall — config reference

Auto-generated by `heimdall init`. Regenerate after upgrading heimdall:

```bash
sudo /usr/local/bin/heimdall init --dir /etc/heimdall --format nickel --force
```

This README plus `lib.ncl` are the AI-readable contract for the config
schema. They version-lock with the daemon — if you upgrade heimdall,
regenerate both.

> **Audience**: this file is dense on purpose. It's the reference an AI
> agent reads when asked "edit /etc/heimdall/heimdall.ncl to do X".

## Directory layout

```
/etc/heimdall/
├── heimdall.ncl    ← main config (loaded by daemon)
├── lib.ncl         ← Nickel schema contracts (imported by heimdall.ncl)
├── README.md       ← this file
└── secrets/        ← 0700 root:root, NOT in git
    └── *.pw        ← 0400 root:root, no trailing newline
```

The daemon probes `/etc/heimdall/heimdall.{ncl,toml,json,yaml}` in that
order and uses the first one that exists, so a typical systemd unit is
just:

```
ExecStart=/usr/local/bin/heimdall serve
```

Override with `--config <PATH>` or `HEIMDALL_CONFIG=<PATH>` if you keep
the file elsewhere.

Format selection is by extension (`.yaml` / `.json` / `.toml` / `.ncl`).
Nickel is recommended because `lib.ncl` validates the whole record at
evaluation time — typos and wrong types are caught before the daemon
ever sees the file. Other formats are validated by
`serde(deny_unknown_fields)` at load time.

## Bootstrap workflow

```bash
# 1. Initialise (writes heimdall.ncl + lib.ncl + this README)
sudo /usr/local/bin/heimdall init --dir /etc/heimdall --format nickel

# 2. Edit /etc/heimdall/heimdall.ncl
sudoedit /etc/heimdall/heimdall.ncl

# 3. (Recommended) Validate before restart
nix-shell -p nickel --run "cd /etc/heimdall && nickel export -f json heimdall.ncl > /dev/null"

# 4. Add any required secrets
sudo install -d -m 0700 -o root -g root /etc/heimdall/secrets
printf '%s' 'PASSWORD' | sudo tee /etc/heimdall/secrets/<name>.pw > /dev/null
sudo chmod 0400 /etc/heimdall/secrets/<name>.pw

# 5. Apply
sudo systemctl restart heimdall
sudo journalctl -u heimdall -n 5 --no-pager | grep "config loaded"
# expected:
#   config loaded path=/etc/heimdall/heimdall.ncl connections=N rules=M ...
```

`heimdall init --force` overwrites existing files. Without `--force` it
bails on any pre-existing target. It does **not** touch `secrets/`.

## Top-level structure

```nickel
let h = import "lib.ncl" in
{
  apiVersion = "heimdall.io/v1alpha1",
  kind       = "HeimdallConfig",

  runtime     = { ... },              # eBPF + listener + retention
  connections = { name = { ... } },   # named SOCKS5 / direct upstreams
  routing     = {                     # systemd-unit selector → connection name
    rules     = [ ... ],
    "default" = { use = "...", observe = ... },
  },
} | h.HeimdallConfig
```

`apiVersion` and `kind` are reserved sentinel strings. They must be
`"heimdall.io/v1alpha1"` and `"HeimdallConfig"` respectively in the
current schema.

## `runtime`

| Key | Type | Default | Meaning |
|---|---|---|---|
| `cgroup` | string | `/sys/fs/cgroup/system.slice` | Primary cgroup subtree for the `connect4` + `connect6` + `skb_egress` BPF attach. The daemon also attaches a secondary at `/sys/fs/cgroup/user.slice` to cover `heimdall run` / interactive user processes. |
| `listen` | string | `0.0.0.0:12345` | Relay TCP listener. The daemon auto-rewrites a v4 wildcard to `[::]:N` for dual-stack accept; explicit IPs are honoured as-is. |
| `relayIp` | string | `127.0.0.1` | IPv4 the relay listens on as seen from intercepted processes. On a single host this stays loopback. |
| `relayIp6` | string | `::1` | IPv6 sibling of `relayIp`. eBPF `connect6` rewrites IPv6 destinations to `relayIp6:listen-port`. |
| `bypassCidrs` | array of string | `[]` | Reserved; not yet wired into eBPF. Built-in bypass list covers loopback, link-local, LAN (v4) and equivalents (v6). |
| `dnsListen` | string | `0.0.0.0:5358` | Fake-IP DNS UDP listener. |
| `fakeIpCidr` | string | `198.19.0.0/16` | IPv4 fake-IP pool (RFC 2544 benchmark range, guaranteed not in real routing). |
| `fakeIp6Cidr` | string | `fc00:198:19::/96` | IPv6 fake-IP pool. AAAA queries get synthetic addresses from this range; relay reverses them at SOCKS5 ATYP=0x03 time. Empty string disables AAAA synthesis. |
| `apiListen` | string | `127.0.0.1:9999` | HTTP API + Web UI. Set `0.0.0.0:9999` for LAN access. |
| `stateDir` | string | `/var/lib/heimdall` | sqlite + future blob storage. systemd creates 0750 root:root. |
| `flowRetentionSecs` | integer | `259200` (3d) | Cleanup task drops `flows` + `messages` older than this. |
| `tap.enabled` | bool | `false` | Master switch for the uprobe tap. When false: no /proc scan, no uprobes, no perf consumer. |
| `tap.persist` | bool | `false` | Within tap, write captured plaintext to the `messages` table. When false, events only show up in journal. |
| `defaultEgressPolicy` | enum `redirect` \| `bypass` | `redirect` | What to do with unclassified cgroups in the attached subtree. `bypass` is the runbook fail-open. |

`tap.enabled=false` overrides `tap.persist`. Tap requires
`CAP_SYS_PTRACE` in the systemd unit (already set in the NixOS module).
The orphan-cgroup GC for `heimdall run` requires `CAP_DAC_OVERRIDE` so
the daemon can rmdir user-owned heimdall-cli-* directories.

## `connections`

A registry of named upstreams. Keys are the connection names referenced
from `routing.rules[].use`.

```nickel
connections = {
  default = {
    description = "Public internet egress (e.g. local SOCKS5 proxy)",
    type        = "socks5",
    addr        = "127.0.0.1:1080",
  },

  # Example: a second upstream for a different egress path. Keys with
  # hyphens or dots must be quoted in Nickel record syntax
  # ("corp-vpn" = ...); use a plain identifier (corpVpn / internal) to
  # avoid the quoting.
  internal = {
    description = "Auth-protected SOCKS5 (e.g. corporate VPN gateway)",
    type        = "socks5",
    addr        = "10.0.0.1:1080",
    auth = {
      username     = "alice",
      passwordFile = "/etc/heimdall/secrets/internal.pw",
    },
  },

  direct = { type = "direct" },
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `type` | enum `"socks5"` \| `"direct"` | yes | |
| `addr` | string | for `socks5` | host:port. |
| `auth.username` | string | optional | RFC 1929 user/pass. |
| `auth.passwordFile` | string | optional | Path read at daemon startup. No trailing newline. |
| `description` | string | optional | Surfaced in API + UI. |
| `owner` | string | optional | Free-form contact. |
| `mitm` | bool | optional | Reserved for a future TLS terminator. Parsed but ignored. |

### Reserved name `system`

`system` is **not** a connection — it's a reserved tag used in `routing`
to mean "no relay redirect; eBPF lets the connection through
untouched." The validator rejects a connection literally named `system`.

This routing tag is **orthogonal to `system.slice`** (the systemd slice)
— naming overlap, different concept.

### Sentinel `default`

There must be a connection named `default`. It's the safety net when
`routing.default.use` resolves to a non-existent name and falls through.

## `routing`

```nickel
routing = {
  rules     = [ ... ],   # ordered list, first match wins
  "default" = { use = "...", observe = bool },
}
```

`"default"` is quoted because `default` is a reserved word in Nickel.
The runtime field name is `default`.

### Resolution order

```
1. first matching rule in routing.rules
2. routing.default
```

`use` and `observe` are evaluated together off the same matched rule
(observe falls through to default when the matched rule omits it).

### Rules

```nickel
rules = [
  {
    name    = "string",          # optional; appears in logs
    "match" = MatchCond,         # optional; absent = catchall
    use     = "default",         # connection name, or reserved "system"
    observe = true,              # optional; omit to inherit routing.default.observe
  },
  ...
]
```

`"match"` is quoted because `match` is a reserved word in Nickel.

`use` MUST be one of:
- A name present in `connections` (case-sensitive, exact match)
- The reserved string `"system"`

Validation rejects unknown names at startup.

Rules are evaluated **in order, first match wins**. Put more specific
rules above more general ones.

## `MatchCond` — the selector grammar

```nickel
{
  # systemd identity selectors
  units            = [ MatchValue, ... ],   # leaf unit (*.service / *.scope)
  slices           = [ MatchValue, ... ],   # enclosing slice (*.slice)

  # Boolean composition — every leaf is itself a MatchCond
  all   = [ MatchCond, ... ],   # AND
  any   = [ MatchCond, ... ],   # OR
  "not" = MatchCond,            # NOT  (`not` reserved in Nickel; quote it)
}
```

The two identity axes are derived from the process's cgroup path:
`units` matches the nearest `.service` / `.scope` leaf (e.g.
`nginx.service`, `run-r1234.scope`); `slices` matches the nearest
enclosing `.slice` ancestor (e.g. `system.slice`, `user.slice`).

All present **fields** AND together. So:

```nickel
{
  slices = [ "system.slice" ],
  units  = [ "regexp:^(nginx|caddy)\\.service$" ],
}
```

…matches "slice is system.slice AND unit is nginx.service or
caddy.service".

An empty MatchCond (or `all = []`) matches everything. Omit `match` on
a rule to make it a catchall.

### `MatchValue` — tag-prefix dispatch

Each entry in `units` / `slices` is a string. A leading tag changes the
comparison:

| Tag | Example | Match |
|---|---|---|
| (none) | `nginx.service` | Exact equality |
| `regexp:` | `regexp:^docker-.+\.scope$` | RE2 regex |
| `prefix:` | `prefix:docker-` | Starts-with |
| `suffix:` | `suffix:.scope` | Ends-with |
| `keyword:` | `keyword:nginx` | Contains substring |

### Boolean composition example

"unit is nginx.service AND (slice is user.slice OR slice starts with
`user-`)":

```nickel
{
  units = [ "nginx.service" ],
  any = [
    { slices = [ "user.slice" ] },
    { slices = [ "prefix:user-" ] },
  ],
}
```

"NOT in system.slice":

```nickel
{
  "not" = { slices = [ "system.slice" ] },
}
```

## `cli` — defaults for `heimdall <subcommand>`

Optional top-level field that lets every CLI default live in the same
config file as routing. Each subcommand hangs its config under
`cli.<subcmd>`. Today only `cli.run` is consumed (the proxychains-style
`heimdall run`).

```nickel
cli = {
  run = {
    # Baseline applied when --profile is not given. Every field optional.
    "default" = {
      connection  = "default",       # connection name (or reserved "system")
      observe     = true,             # capture plaintext via the tap
      dns         = "fake",           # "fake" | "system" — DNS strategy
      timeout     = 0,                 # seconds; 0 = no timeout
      extraBypass = [],                # extra CIDRs to bypass for this command
      tag         = "",                # free-form label, surfaces in flow log
    },

    # Named profiles selectable via --profile NAME. Inherits from
    # default; override only the fields you care about.
    profiles = {
      internal = { connection = "internal" },
      peek     = { tag = "interactive-debug" },
      silent   = { observe = false },
    },
  },
}
```

### `cli.run.*.dns`

| Value | Behaviour |
|---|---|
| `"fake"` (default) | Hijack DNS lookups for the wrapped command's cgroup so heimdall's fake-IP DNS sees them. Two layers stacked: eBPF rewrites any `:53` connect / sendmsg destination to the daemon, AND `heimdall run` enters a private user+mount namespace with a stripped-down `/etc/nsswitch.conf` and a single-entry `/etc/resolv.conf` so libc's `getaddrinfo` issues `127.0.0.1:53` queries that hit heimdall's fake-IP DNS regardless of the host's `nss-resolve` / nscd setup. |
| `"system"` | Skip the shim entirely. Wrapped command uses the host's normal resolver. |

### Resolution order for `heimdall run`

```
flag (e.g. --connection X / --dns system)
  > [profile.NAME] in cli.run.profiles
  > cli.run.default
  > compiled-in fallback (connection="default", observe=true, dns="fake")
```

### Lifecycle: orphan-cgroup GC

When a `heimdall run` invocation exits cleanly the wrapping process
deregisters the cgroup_id with the daemon and rmdirs the transient
cgroup. `kill -9`, OOM kill, and other abnormal exits leak both the
cgroup directory and the BPF policy entry.

The daemon runs a periodic GC pass (every 30s) that walks
`/sys/fs/cgroup/user.slice` for `heimdall-cli-*` directories with
`cgroup.events: populated 0` (no live processes), and tears down: the
userspace `cli_overrides` entry, the `PolicyEngine.external` set entry,
the `CGROUP_POLICY` BPF map row, and rmdirs the directory. Idempotent
and safe to leave running indefinitely.

## Reserved fields and edge cases

| Item | Behaviour |
|---|---|
| `apiVersion` != `"heimdall.io/v1alpha1"` | Validation error at load. |
| `kind` != `"HeimdallConfig"` | Validation error at load. |
| `connections.system` | Rejected (reserved tag). |
| `routing.rules[].use = "non-existent"` | Rejected at startup. |
| `connections.<name>` missing for `auth.passwordFile` | Daemon startup fails reading the file. |
| Empty `routing.rules` | OK; everything falls to `routing.default`. |
| `routing.default.use = "system"` | OK (everything skips the relay by default). |
| Unknown field anywhere (Nickel) | Caught by `lib.ncl` contract at evaluation. |
| Unknown field anywhere (YAML/JSON/TOML) | Caught by `serde(deny_unknown_fields)` at load. |

## Validation — what the daemon checks at startup

Order of operations:

1. Load + parse the file according to its extension.
2. Run schema-level validation (`serde` for non-Nickel; `lib.ncl` for
   Nickel runs at file-evaluation time before this point).
3. Validate cross-references: every `routing.rules[].use` exists in
   `connections` or equals `"system"`; `routing.default.use` similarly.
4. Read every `connections.<name>.auth.passwordFile`.

Failures at any step abort startup — heimdall does NOT serve a partial
config.

## Smoke test

After any change, verify the routing decision via the flows API:

```bash
# 1. Generate traffic from a transient unit you can name
sudo systemd-run --unit=heimdall-smoke --collect -- \
  curl -ksSm 5 -o /dev/null https://www.cloudflare.com/

# 2. Inspect the resulting flow
curl -sS "http://127.0.0.1:9999/api/flows?limit=20" | python3 -c '
import json, sys
for f in json.load(sys.stdin):
    if f["connection_name"] == "bypass": continue
    dst = f["dst_host"] or f["dst_ip"]
    slice = f["slice"] or "-"
    unit  = f["unit"]  or "-"
    print(f"slice={slice:20s} unit={unit:40s} → {f[\"connection_name\"]:10s} {dst}:{f[\"dst_port\"]} atyp={f[\"atyp\"]}")
'
```

Expected:
- `connection_name` matches the `use:` your rule resolved to.
- `dst_host` non-empty (`atyp=domain`) when fake-IP DNS round-tripped.
- `dst_host` null with IP literal (`atyp=ip`) when the process connected
  by raw IP — the relay handled it via SOCKS5 ATYP=0x01.

For units routed to `use: system`, **no flow record appears** (eBPF lets
the connection skip the relay entirely).

For traffic where `dst_ip` is in the host bypass list, you'll see
`connection_name: "bypass"` — that's the synthetic log the eBPF bypass
path emits, not a real relay flow.

## Common errors

| Symptom | Cause | Fix |
|---|---|---|
| `unknown use 'foo' in rule` at startup | Misspelled or removed connection | Fix `use:` to a real connection name or `"system"`. |
| `connections registry: 'system' is reserved` | Declared `connections.system` | Drop that entry; use `use: system` in a rule instead. |
| `cannot read passwordFile: ...` | Missing or wrong-permissions secret | `chmod 0400` and `chown root:root /etc/heimdall/secrets/<name>.pw`. |
| All flows show `connection_name: "bypass"` | Traffic targets host bypass list (loopback/LAN) — expected | Generate external traffic to test relay path. |
| `nickel: command not found` outside systemd | `nickel` not on user PATH | `nix-shell -p nickel --run ...` or `nix profile install nixpkgs#nickel`. |
