Platform / reduced scope

macOS backend

macOS x86_64/aarch64 supports architecture-neutral explicit for SOCKS-aware clients. Apple silicon additionally supports interpose for compatible dynamic calls. Neither claims Linux eBPF-equivalent command scope.

No app or service. Both backends live in the single CLI, change no system proxy or keychain state, and remove their listener and run state when the foreground command exits.

Quick start

[execution]
backend = "explicit" # Apple silicon may instead select "interpose".

[proxy.policies.default.final]
tcp = { type = "route", outbound = "default" }
udp = { type = "reject", method = "refused" }

[capture]
mode = "off"

[decrypt]
mode = "off"
heimdall agent --policy default
heimdall run --policy default -- curl https://example.com

macOS requires an explicit backend choice. Use explicit on x86_64 or Apple silicon; interpose is an additional Apple-silicon choice, and ebpf is unavailable. Use Agent v10's exact actions.execute_prefix in automation.

Both implemented paths require rejected UDP and disabled capture/TLS. explicit additionally requires system DNS. Neither changes machine-wide settings or starts a daemon.

How interpose works

command
  → embedded dylib materialized privately for one run
  → child-only DYLD injection
  → per-run secret authenticates to loopback SOCKS5
  → shared route / direct / reject TCP policy
  → JSONL finalization and dylib removal

Hooked libc resolution returns a per-run synthetic address so a later hooked TCP connect preserves the original hostname. Common interposed IP-datagram calls are rejected. This is not raw DNS or UDP interception.

The reported scope is interposed_dynamic_calls with failure_boundary=interposed_calls_only and client_can_bypass=true. SIP-protected and detected Hardened Runtime targets fail preflight. connectx, Network.framework, direct syscalls, alternate UDP APIs, and descendants that discard loader state remain outside the hook set.

Events use source={backend:"interpose", scope:"interposed_dynamic_calls"}. Explicit mode uses source={backend:"explicit", scope:"cooperative_environment"}. These values prove frontend use, not operating-system process attribution.

Deferred Network Extension

The repository retains a compile-only NETransparentProxyProvider skeleton and authenticated Rust/Swift control codec. It cannot activate or save network configuration, refuses provider startup, is excluded from package/release construction, and reports release_included=false. Reopening this path would require a separate roadmap decision, Apple entitlements, signed installation and approval, coexistence tests, and reliable command attribution.

Native acceptance and release

just test-macos-explicit-native
just test-macos-native
just test-macos-interpose-native

The explicit gate runs on either native macOS architecture. The combined and interpose gates remain Apple-silicon-only. Together they cover config selection, Agent v10, authenticated real TCP routing, hostname preservation, common UDP-call rejection, JSONL integrity, cleanup, exit status, explicit proxy behavior, and protected-target preflight. A publishable macOS archive still requires Developer ID signing of the CLI and embedded dylib, notarization, Gatekeeper, and fresh-download install, run, upgrade, rollback, and uninstall acceptance.
