System / data path

Architecture

Heimdall has one product path: wrap a command and proxy that command's outbound connections. The control plane selects a policy; the data plane enforces it only for that command scope.

The mark is a guarded crossing.The navy arch is the boundary; the spectrum path is Bifröst; a command crosses only inside its registered policy scope.

The path at a glance

heimdall run -- commandone registered cgroup
01 / CLIcommand scopeRuns the command and keeps descendants together.
→
02 / KERNELcgroup eBPFRedirects registered TCP and UDP.
→
03 / RELAYrelay + policyRecovers destination identity.
→
04 / OUTBOUNDroute / direct / rejectApplies the first match.

Boundaries

The CLI is the product surface. It selects a named policy, creates a child cgroup, executes the requested command, forwards its exit status, and cleans up.

The daemon owns the relay, fake-IP DNS, loopback control endpoint, eBPF maps, and stale cgroup cleanup. Its default eBPF policy is bypass, so an unregistered process cannot be redirected accidentally.

Loopback is deliberate.The internal relay binds fixed IPv4 and IPv6 loopback sockets on port 12345. These endpoints cannot be exposed or made inconsistent with eBPF by configuration.

Connection lifecycle

  1. heimdall run re-enters through systemd-run --user --scope when it needs an isolated delegated cgroup.
  2. The CLI registers that cgroup ID and policy name with the local daemon.
  3. The child joins the cgroup and executes the requested command.
  4. eBPF rewrites eligible TCP and UDP destinations to the local relay. DNS follows the selected fake or system mode.
  5. The relay recovers the original destination, evaluates ordered rules, and routes, connects directly, or rejects.
  6. After the immediate child exits, the daemon keeps the policy registered until the complete descendant tree leaves the cgroup.

Three independent data boundaries

LayerDecisionDefault
ProxyWhether and where a connection is relayed.Policy required
CaptureWhether bounded bytes are retained as JSONL.off
DecryptWhether retained TLS bytes are runtime-probed or relay-terminated.off

Heimdall never infers plaintext from a port or filename. Read the running capability evidence from heimdall agent before consuming capture data.

Non-goals

  • Cluster or container orchestration integration.
  • Host-wide routing rules for services.
  • Workload labels, annotations, or admission hooks.
  • A web UI or public HTTP API as the primary interface.
