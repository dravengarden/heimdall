System / data path

Architecture

Heimdall wraps one command, selects a configured backend, and owns one foreground relay. Linux eBPF provides strict command-cgroup scope; reduced backends state exactly which client calls they can see.

The mark is a guarded crossing.The navy arch is the boundary; the spectrum path is Bifröst; a command crosses only inside its attached policy scope.

Boundaries

The foreground CLI is the session owner. Every backend selects a policy, binds its per-run relay, executes the command, and closes all owned resources. Linux ebpf additionally creates a child cgroup and DNS listener and waits for every descendant.

The platform-neutral relay_transport core resolves outbound credentials once and owns SOCKS5 TCP CONNECT, UDP ASSOCIATE, destination encoding, response validation, and setup timeouts. Linux ebpf owns cgroup interception, original-destination correlation, TCP/UDP listeners, UDP identity, capture, and TLS. interpose and explicit reuse only the shared TCP path behind reduced frontends.

A root setup worker validates one cgroup, attaches fresh unpinned maps and FD-owned eBPF links, transfers those FDs, and drops to the invoking user before the workload starts. Every run keeps that helper as a parent-death guard; runtime TLS also uses it to retain probe state. Unmarked owner exit kills and removes only that command cgroup. It never reads proxy credentials, captures bytes, or keeps a listener.

Runtime TLS pre-attaches supported OpenSSL images found in active mappings, standard library directories, and /etc/ld.so.conf. A loader-known image may map after child exec because the probe already owns its inode. Private images outside those paths remain opaque; the setup helper does not retain privilege to monitor the workload.

No persistent daemon. Every implemented backend uses kernel-assigned loopback relay ports per run. The eBPF backend additionally owns per-run IPv4/IPv6 fake-DNS listeners; its session helper has no listener and exits with the foreground invocation.

Reduced daemonless paths

heimdall run --backend interpose -- command
  → embedded private .so/.dylib
  → authenticated per-run SOCKS5 CONNECT
  → shared TCP policy → SOCKS5 / direct / reject

heimdall run --backend explicit -- command
  → child ALL_PROXY/all_proxy
  → cooperative per-run SOCKS5 CONNECT

interpose is selectable on Linux and Apple silicon. It routes compatible dynamic TCP connect and libc getaddrinfo calls and rejects common interposed UDP sends. Static code, direct syscalls, alternate APIs, loader removal, inherited sockets, and unsupported descendants can bypass it. JSONL uses source={backend:"interpose", scope:"interposed_dynamic_calls"}.

Linux/macOS x86_64/aarch64 explicit supplies only child SOCKS variables and requires system DNS. JSONL uses source={backend:"explicit", scope:"cooperative_environment"}. Both reduced paths require rejected UDP and capture/decrypt off, start no daemon, and claim no payload, TLS, strict process scope, or universal fail-closed behavior. macos-transparent remains deferred and excluded from releases. Read the macOS decision →

For a plain hosts: files dns NSS path, the cgroup hooks redirect resolver port-53 traffic directly, including a systemd-resolved loopback stub. No user or mount namespace is needed. NSS modules or caches that bypass port 53 retain the private resolver-mount fallback; pinned Debian 13 exercises that path with its stock files myhostname resolve [!UNAVAIL=return] dns chain. Setup fails before command execution if the required scoped namespace is unavailable.

The read-only agent preflight uses the same classifier. decision.resolver reports its strategy, reason, hosts sources, nscd socket, AppArmor/userns settings, private-mount status, readiness, and stable error. A known system-wide disablement withholds actions.execute_prefix; an AppArmor restriction remains a runtime policy check because an exact-path profile may permit only Heimdall.

Connection lifecycle

  1. heimdall run re-enters through systemd-run --user --scope when it needs an isolated delegated cgroup.
  2. The CLI binds per-run relay and DNS listeners, then the authorized setup worker attaches eBPF and drops privilege.
  3. The child joins the cgroup only after setup succeeds, then executes the requested command.
  4. eBPF rewrites eligible TCP and UDP destinations to the local relay. DNS follows the selected fake or system mode.
  5. The relay recovers the original destination, evaluates ordered rules, and routes, connects directly, or rejects.
  6. The run writer records correlated fake-DNS exchanges, policy decisions, flow boundaries, parsed relay ClientHello, and explicit runtime/relay TLS observations.
  7. After the immediate child exits, the foreground owner keeps interception alive until the complete descendant tree leaves the cgroup, then closes links, maps, listeners, and logs.

Heimdall never infers plaintext from a port or filename. Read the running capability evidence from heimdall agent before consuming capture data.

Non-goals

  • Cluster or container orchestration integration.
  • Host-wide routing rules for services.
  • Workload labels, annotations, or admission hooks.
  • A web UI or public HTTP API as the primary interface.
