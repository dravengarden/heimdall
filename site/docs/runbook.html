Operate / verify

Runbook

Use repository-owned commands inside the pinned Nix shell. Build eBPF before userspace because the object is embedded in the single CLI.

Build and verify

nix develop -c just sync-ebpf
nix develop -c just verify

just verify includes format, lint, dependency, unit, Darwin type-check, site, release-tooling, userspace, and Linux interpose-native gates.

macOS native gates

# x86_64 or Apple silicon
just test-macos-explicit-native

# Apple silicon
just test-macos-native
just test-macos-interpose-native

# Deferred source only:
just test-macos-companion-native

test-macos-explicit-native accepts explicit mode on either macOS architecture by routing curl through its cooperative listener. The Apple-silicon combined gate additionally verifies the embedded interpose dylib, per-run authentication, real TCP policy routing, hostname preservation, common UDP-call rejection, Agent v10, JSONL integrity, cleanup, exit status, and protected-target preflight.

The companion gate builds no release artifact and proves no Network Extension installation, activation, routing, or attribution.

Config and smoke test

heimdall config validate --json
heimdall agent --policy default | jq .
heimdall run --policy default -- curl -fsS https://example.com

Select every backend explicitly. Linux supports ebpf, interpose, and explicit. macOS x86_64/aarch64 supports explicit; Apple silicon additionally supports interpose. Heimdall never guesses or falls back.

Inspect evidence

heimdall logs list --json
heimdall logs summary --run RUN_ID --json | jq .
heimdall logs flow --run RUN_ID --flow FLOW_ID --json | jq .
heimdall logs verify --run RUN_ID --json

JSONL is the source of truth. Agent v10 and all log schemas are available offline. Reduced backend events carry interpose/interposed_dynamic_calls or explicit/cooperative_environment source metadata and intentionally do not imply process attribution.

Release boundary

The local release transaction is authoritative: build immutable assets, inspect them, run platform gates, render changelog-backed notes, then publish. Thin npm, PyPI, and crates.io OIDC workflows upload only those release assets; they do not rebuild Heimdall.

A macOS version is publishable only after the CLI and embedded dylib receive Developer ID signatures, notarization succeeds without warnings, Gatekeeper accepts the result, and a fresh download passes install, run, upgrade, rollback, and uninstall.
