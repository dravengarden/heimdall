Operations / evidence first

Runbook

Build the eBPF object before userspace, install the daemon with its privilege boundary intact, and verify the running contract rather than trusting a successful compile.

Build

The daemon embeds the eBPF ELF, so eBPF must be built first. Enter the pinned development environment before running project commands.

nix develop .#ebpf -c bash -c \
  'cd heimdall-ebpf && cargo-nightly build --locked --release'
nix develop -c just verify

Run the disposable real-eBPF VM when changing cgroups, DNS, relay correlation, routing, or kernel programs:

nix develop -c just test-vm

Install

sudo install -Dm755 target/release/heimdall /usr/local/bin/heimdall
sudo /usr/local/bin/heimdall init
sudo install -Dm644 deploy/heimdall.service \
  /etc/systemd/system/heimdall.service
sudo systemctl daemon-reload
sudo systemctl enable --now heimdall

The daemon should bind only loopback listeners. Confirm the relay reports both loopback families and inspect the service state:

heimdall status
systemctl status heimdall
journalctl -u heimdall -n 100

Smoke test

heimdall agent | jq .
heimdall config validate
heimdall run -- curl -fsS https://example.com
Exit status is part of the contract.The wrapped command's exit status is Heimdall's exit status. A daemon or registration failure happens before the command is executed.

Acceptance coverage

The VM exercises real eBPF attachment, fake and system DNS, SOCKS5 IPv4/IPv6/domain requests, connected and connectionless UDP, QUIC, descendant lifetime, signal propagation, daemon recovery, fail-closed upstream errors, and TLS capture paths.

EvidenceWhat it proves
just verifyBuild, format, lint, dependency, unit, and userspace gates.
just test-vmReal kernel data path and compatibility matrix.
heimdall agentRunning config, daemon readiness, capabilities, and repair actions.
heimdall statusOperational daemon and relay state.

Diagnose failures

  1. Run heimdall agent and preserve its JSON even when it exits 1.
  2. Follow its actions.validate or actions.status argv array.
  3. If the daemon is unavailable, inspect recent service logs.
  4. Preview the destination with heimdall config explain --json.
  5. Reproduce with a small command such as curl, preserving the same policy.
journalctl -u heimdall --since "10 min ago" --no-pager

Do not equate config validity with connectivity. A real acceptance check must exercise the selected policy through heimdall run.

Persistent eBPF cleanup

Only for an explicitly requested uninstall or schema repair:

sudo systemctl stop heimdall
sudo heimdall ebpf cleanup --json
Never unlink pins manually. Cleanup refuses to remove state while the daemon or active workloads still own it.
