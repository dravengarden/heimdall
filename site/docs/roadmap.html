Product / acceptance

Roadmap

Status follows evidence, not dates. A capability is available only when its contract, failure behavior, and relevant native or real-kernel gate pass.

Available

  • Linux cgroup eBPF TCP/UDP policy, fake/system DNS, direct or SOCKS5 routing, capture, and optional runtime/relay TLS.
  • Required execution.backend = ebpf | interpose | explicit configuration with no fallback.
  • Linux and Apple-silicon interpose with authenticated per-run TCP relay, libc hostname preservation, common interposed UDP-call rejection, and explicit bypass reporting.
  • Linux and macOS x86_64/aarch64 explicit for cooperative SOCKS-aware TCP clients.
  • No persistent daemon or required Web UI in any implemented backend.
  • heimdall.agent/v10, append-only JSONL, offline schemas, integrity checks, rotation, recovery, bounded run summaries, and per-flow explanations.
  • Static x86_64/aarch64 Linux packages and source package workflows for npm, PyPI, and Cargo.
Reduced means reduced. Interpose and explicit do not claim strict process scope, UDP proxying, payload capture, TLS inspection, QUIC, or universal fail-closed behavior.

In development

Track 01

Compatibility

Expand eBPF distribution/kernel coverage and interpose runtime fixtures without broadening either contract from a compile result.

Track 02

Evidence

Keep JSONL bounded, recoverable, provenance-linked, and directly useful through ordinary Linux commands and Agent v10.

Track 03

Native ARM

Add repeatable aarch64 Linux real-eBPF current/LTS acceptance when an ARM executor is available.

Track 04

macOS release

Publish only after Developer ID signing, notarization, Gatekeeper, and fresh-download install/run/upgrade/rollback/uninstall acceptance.

Deferred

  • The checked-in NETransparentProxyProvider app/system-extension prototype remains source-only and excluded from releases.
  • No host-wide VPN, always-on proxy, cluster control plane, or required desktop dashboard.
  • No persistent acceleration daemon unless future measurements establish a need and an explicit optional profile is designed.
